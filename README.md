# 메이플스토리 MVP작 계산기

## 2026-09-17 마일리지 개편 반영

[공식 개편 공지](https://maplestory.nexon.com/news/update/813) 기준으로 계산 모델을 바꿨습니다.

- 넥슨캐시 결제액의 **5%가 메이플크레딧으로 적립**되고, 크레딧은 **크레딧샵에서만** 사용합니다. 10캐시 미만 상품과 선물 결제는 적립 제외입니다.
- **상품가 30% 마일리지 병용 결제는 폐지**되어 계산에서 제거했습니다. 기존 마일리지 잔액은 2026-11-19 점검 후 소멸하므로 이 계산기에서 사용하지 않습니다.
- 따라서 적립 크레딧의 가치는 **크레딧샵 상품을 사서 팔았을 때의 메소**로만 정해집니다. 크레딧샵 상품을 별도 표에 넣고, 캐시 상품과 함께 구매 수량·순서를 계산합니다.
- 두 화폐(캐시·크레딧)의 잔액과 상품별 수량 한도를 결제 전에 검사합니다. 크레딧 구매는 어떤 캐시 구매도 열어 주지 않으므로 계획은 항상 **캐시 결제를 모두 마친 뒤** 크레딧샵 구매로 실행할 수 있습니다.
- 저장 키가 `mvp-calc-v5`로 바뀌어 예전 마일리지 설정은 불러오지 않습니다. 내보낸 JSON에는 `creditItems`가 추가됐습니다.

## 선물형 MVP작 비교

선물형은 MVP 1만원을 정해진 현금(기본 7,000원)으로 채우는 방식입니다. 받은 상품을 팔지 않아 **회수 현금이 없고**, 선물 결제라 **크레딧도 적립되지 않습니다**. 비용 전부가 손실입니다.

- 선물형 환산 회수율 = 1 − 선물형 비용 ÷ (10,000 × 충전 비율). 기본값(7,000원, 93%)이면 **24.73%**입니다. 계획의 회수율이 이보다 높으면 같은 MVP를 일반 MVP작으로 채우는 쪽이 쌉니다.
- 결과에는 사용 캐시를 MVP 금액으로 보고, 같은 금액을 선물형으로 채우는 비용(사용 캐시 × 선물형 비용 ÷ 10,000)과 계획의 실비용(원가 − 회수 현금), MVP 1만원당 실비용을 함께 표시합니다.
- 전역 설정의 `선물형 비용` 칸을 비우면 비교를 숨깁니다. 계산식은 `optimizer.js`의 `giftCompare`입니다.

## 로컬 캐시 상품 자동 시세

로컬(`localhost`/`127.0.0.1`)에서 계산하면 `maple-market` 수집 서버에 당일 시세를 요청합니다. 최초 요청만 공지와 옥션 수집을 시작하며 그날의 다른 사용자는 저장된 결과를 공유합니다. 페이지를 열기만 해서는 검색하지 않습니다. `계산할 때 캐시 상품 시세 자동 반영`을 끄면 기존 수동 계산을 사용합니다.

- `maple-market`의 새 웹 서버와 워커가 실행 중이어야 합니다. 기본 연결 주소는 `http://127.0.0.1:3000`이며 로컬 서버의 `MAPLE_MARKET_URL` 환경변수로 변경할 수 있습니다.
- `http://127.0.0.1:3000/admin/cash-shop`에서 고정 4종의 캐시 원가·적립 여부, OCR로 추출한 기간 한정 상품의 구성, **크레딧샵 상품 목록**을 확인합니다. 확률형 결과물은 제외합니다.
- 크레딧샵 상품은 **매월 그 달의 첫 수집에서만 전 상품을 조회**해 `메소 ÷ 크레딧` 효율 상위 절반만 남기고, 나머지는 그 달 동안 검색하지 않습니다. 제외된 상품과 사유는 크레딧샵 표 아래에서 볼 수 있습니다.
- 자동 관리 행만 당일 결과로 갱신하며 직접 입력 행과 자동 상품의 최대 수량은 보존합니다. 미확인 캐시 원가·적립 여부·크레딧 가격, 매물 없음, 일부 선택지 누락은 별도로 표시합니다.
- 남녀 선택은 실제 받을 수 있는 묶음별 합계 중 높은 쪽을 사용합니다. 판매 등록 최저가이며 실제 체결가는 아닙니다.
- 실패한 수집은 후속 사용자 요청으로 반복 실행하지 않습니다. 수동 모드로 계산하거나 다음 날 요청하세요.
- 이번 연동은 로컬 전용입니다. 현재 배포된 정적 사이트는 변경하지 않았습니다. 외부 배포에는 수집 서버의 HTTPS 연결이 추가로 필요합니다.

브라우저에서 캐시 결제와 크레딧샵 구매 조합, 실행 순서를 계산하는 정적 사이트입니다. 서버 API, 데이터베이스, 외부 라이브러리가 필요하지 않습니다.

## 화면

- **목록 접기**: 캐시템 목록과 크레딧샵 상품의 제목 옆 화살표로 표를 접습니다. 접어도 제목 아래 한 줄 요약(상품 수, 계산 가능 수, 최고 회수율·효율)과 시세 상태, 계산 버튼은 남습니다. 접은 상태는 이 브라우저(`localStorage` `mvp-fold-v1`)에 남고, 입력 오류가 접힌 표 안에 있거나 행을 추가하면 저절로 펼칩니다.
- **라이트·다크 테마**: `maple-market`의 토큰과 같은 값이며 `index.html`의 `:root`(라이트)와 `:root[data-theme="dark"]`에 있습니다. `/mvp`로 서빙될 때 상단 메뉴의 스위치로 바꾸고, 선택은 시세·사냥 기록과 같은 `localStorage` `theme`을 씁니다. 저장된 선택이 없거나 단독 배포본이면 시스템 설정을 따릅니다.

## 실행과 검증

Node.js에서 `npm test`로 테스트, `npm run build`로 정적 파일 생성, `npm start`로 로컬 실행합니다. 로컬 주소는 http://127.0.0.1:4173 입니다. HTML 파일을 직접 열면 Web Worker 보안 정책 때문에 계산이 동작하지 않을 수 있습니다.

`dist/`의 여섯 파일만 정적 호스팅에 올리면 됩니다. 빌드 명령은 `npm run build`, 배포 디렉터리는 `dist`입니다. 비밀키나 환경변수는 없습니다. `.openai/hosting.json`은 연결한 Sites 식별자를 보관합니다.

## 계산 전제와 남은 개선점

1. 목표는 예산 이하에서 **획득 메소 최대화**입니다. 특정 MVP 등급 달성에 필요한 최소 캐시 소비 제약은 아직 없습니다. 목표 금액을 반드시 소비하는 조합은 별도 기능이 필요합니다.
2. 메포는 캐시와 1:1의 실효 구매 비용이라고 가정합니다. 전환 단위, 메포 보유분, MVP 인정 대상 여부는 모델에 별도로 포함하지 않습니다.
3. 경매장 수수료는 상품별 동일하며 순수익 메소는 건별 내림합니다. 물량을 얼마나 소화할 수 있는지는 아래 **세 가지 계산**으로 나눠 봅니다. 판매기간은 추천과 판매량 고려 모드에 반영합니다. 경쟁 매물과 실제 호가 잔량은 읽지 않으며, 단가 하락은 거래량에 대한 가정입니다.
4. 적립 크레딧은 **구매 1건마다 정수 내림**합니다. 상품별 실제 적립 단위와 넥슨ID 단위의 적립 한도는 직접 확인해야 하며, 묶음 상품은 한 행에 묶음 가격/판매액으로 입력합니다.
5. 크레딧샵 상품의 월 구매 한도는 자동으로 알 수 없습니다. 관리자 목록의 `monthlyLimit` 또는 계산기의 최대 수량에 직접 넣으세요. 크레딧 유효기간(적립 후 1년)은 계산에 반영하지 않습니다.
6. 큰 입력은 근사 탐색입니다. 모든 규모에서 최적성을 보장하려면 정확한 정수계획법과 구매 순서 제약을 결합한 엔진이 후속 과제입니다.
7. 이미 보유한 크레딧의 취득 원가, 거래 실행, 실시간 시세 조회, 개인 간 데이터 동기화는 포함하지 않습니다.

## 추천과 비교

기본 탭은 **판매 현실 반영 · 추천**입니다. 같은 예산으로 다음 세 결과를 비교합니다.

| 모드 | 판매량 제한 | 예상 단가 |
| --- | --- | --- |
| 판매 현실 반영 · 추천 | 판매기간과 점유율에 따른 공유 한도 | 구성품 누적 판매량에 따라 하락 |
| 판매량 고려 | 추천과 같은 공유 한도 | 입력 단가 고정 |
| 최고 효율 · 비교용 | 입력한 구매 한도만 적용 | 입력 단가 고정 |

기본 입력값은 판매기간 7일, 점유율 5%, 가격 구간 폭 1%, 구간당 하락 15%입니다. 시장 관측으로 검증된 예측값이 아닌 조정 가능한 가정입니다. 기존에 저장한 점유율/하락 설정은 유지됩니다.

- 기간 예상 거래량 = 관측 거래량 / 관측일수 × 판매기간
- 판매 한도 = floor(기간 예상 거래량 × 판매 점유율)
- 가격 구간 폭 = max(1, floor(기간 예상 거래량 × 구간 폭 비율))
- n번째 구성품 단가 = floor(기본 순수익 × max(0, 1 - 하락률 × floor((n - 1) / 구간 폭)))

캐시 구매, 크레딧 구매, 패키지가 같은 옥션 아이템을 포함하면 구성품 이름을 기준으로 수량과 가격 구간을 공유합니다. 패키지에 두 개 들어 있으면 판매 한도를 두 개 차감합니다. 여러 구성품이 있는 패키지는 각각의 한도를 지켜야 합니다. 경로별 관측값이 다르면 더 작은 판매 한도와 단가를 사용합니다. 상품별 구매 한도도 별도로 유지합니다.

예를 들어 주간 거래량 100개, 점유율 10%면 동일 아이템을 어느 경로에서 사든 합계 10개까지입니다. 구간 폭 2%, 하락률 20%면 2개씩 최초 단가의 100%, 80%, 60%, 40%, 20%로 계산합니다. 구매 경로가 바뀌어도 최초 단가부터 다시 시작하지 않습니다.

자동 상품은 서버가 제공한 선택 구성품과 관측기간을 사용합니다. 24시간이 지난 거래량은 API에서 제외합니다. 직접 입력한 상품은 새 **최근 7일 거래량** 칸에 수량을 입력합니다. 구성품 거래량이 없으면 추천/판매량 고려에서 제외하고 사유를 표시합니다. 메소마켓은 판매량 대신 입력한 구매 한도를 적용합니다.

결과에 판매기간·점유율·하락 조건과 판매 미보장 안내를 표시합니다. 실제 호가 잔량, 경쟁 매물, 시장 추세를 추정하는 모델은 아니므로 판매 가능성과 가격을 보장하지 않습니다. 큰 문제에서는 탐색 제한으로 최적해가 보장되지 않는다는 안내도 유지합니다.

이 변경은 대화형 MVP 계산기의 추천 모드에 적용됩니다. /recovery의 일별 기록은 저장된 기존 프로필과 고정 단가의 판매량 기준을 유지하며, 과거 기록을 다시 계산하지 않습니다.
